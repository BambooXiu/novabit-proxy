# Xray DNS 与安全激活实施计划

> 目标：修复 DNS 分流配置被 Xray 忽略的问题，并让部署、模式切换与配置优化在校验失败或服务启动失败时保留可工作的旧配置。

## 1. DNS 分流

- 将 DNS 服务器的无效 `outboundTag` 改为 Xray 支持的 `tag`。
- 在路由中用 `inboundTag` 把 DNS 查询分别送往 `proxy` 或 `direct`。
- 只拦截本地 SOCKS/HTTP 入站的 53 端口流量，防止 Xray 自己发起的 DNS 查询再被送回 `dns-out`。
- 添加服务端对应的 DNS 查询路由。

## 2. 安全写入与模式切换

- 新配置先写入临时文件，并用 `xray run -test -config` 校验。
- 校验通过后才替换正式配置；重启与服务状态检查失败时恢复备份并重启旧配置。
- 部署过程在正式启用前校验两种模式配置。
- 远端 `xray-switch` 脚本复用同样的校验与回滚协议。

## 3. 优化脚本

- 优化脚本对每个 JSON 使用同目录临时文件写入、校验、原子替换。
- 先处理备用模式，最后处理当前生效配置，避免部分失败使线上服务读取到未经校验的内容。
- 优化后的服务重启失败时恢复当前配置备份。

## 4. 验证

- 扩展 Node 内置断言测试，覆盖 DNS 标签/路由范围、模式切换命令的校验与回滚，以及优化脚本的原子校验写入。
- 运行 `npm test`、Node 语法检查和 Git whitespace 检查。
